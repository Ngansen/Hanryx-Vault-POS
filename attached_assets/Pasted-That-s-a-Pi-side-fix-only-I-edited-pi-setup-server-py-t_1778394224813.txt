Both endpoints, with full request/response shapes:

GET / POST /card/enrich — full card detail
The richest single-card lookup. Combines local inventory + Pokémon TCG API (24 h cached) + last-known market price.

Request — three ways to ask
Form	Example
By QR / set-num	GET /card/enrich?qr=SV1-1
By name + set	GET /card/enrich?name=Charizard&set=sv3
By set + number	GET /card/enrich?set=SV1&num=25
POST JSON	POST /card/enrich body {"qr":"SV1-1"} (or {"name":"Charizard","set":"sv3"})
qr accepts the canonical "SET-NUM" form (e.g. SV1-25) or the raw scan string — the server normalises it.

Errors

Side effect
Every successful enrich with a TCGPlayer market price writes a row to the price_history table for trend tracking — so you can later chart how a card's value moves over time.

POST /market/price — your store's local market price
A weighted blend of three trust-tiered sources. This is what the trade-in calculator and the cart "Estimate" chip on the tablet use.

Request body
{
  "name":         "Charizard ex",      // required (text-search key)
  "language":     "EN",                // optional, default "EN"
  "store_price":  39.99,               // optional fallback the caller already knows
  "set_code":     "SV1",               // optional — narrows to exact card
  "card_number":  "025"                // optional — combined with set_code for exact match
}
If set_code + card_number are both provided, the server tries an exact lookup first (SV1-025). Otherwise it falls back to a fuzzy LIKE %name% search over local inventory.

Response (200 OK)
{
  "marketPrice":    41.00,        // ← the answer (weighted average)
  "confidence":     "high",       // "high" | "medium" | "low" | "none"
  "localSalesAvg":  42.50,        // your store's 30-day avg sale price
  "localSales30d":  4,            // how many of these you've sold in 30 days
  "tcgdbPrice":     40.00,        // local inventory DB median price
  "tcgdbName":      "Charizard ex",
  "tcgdbSet":       "SV1",
  "tcgdbRarity":    "Double Rare",
  "storePrice":     39.99,        // echoed back from request
  "language":       "EN"
}
Weighting (how marketPrice is computed)
Source	Weight	When it counts
Your 30-day sale_history avg	3	You've actually sold ≥1 of this card recently — most trusted
Local inventory DB price (median of top 10 matches)	2	The card exists in your TCG DB import
Caller's store_price	1	Fallback only — the price the cashier was looking at
marketPrice = Σ(price × weight) / Σ(weight) over whatever sources returned a value.

Confidence rules
Value	Meaning
"high"	You've sold ≥3 of this card in the last 30 days. Use the price as-is.
"medium"	At least 2 sources agreed (combined weight ≥4) — solid but no recent sales.
"low"	Only one source replied — best guess, ask before honoring.
"none"	Nothing matched. marketPrice will be 0.0.
Important: this is the local price route
There's also the heavier external lookup (/market/price on the cloud repl, which hits pokemontcg.io + the TCGPlayer search API) — that's used for fresh first-time prices. The Pi's /market/price is the fast offline-friendly one and only consults what's already in your store's database.

When to use which
Scanning a card to add to cart / trade-in? → POST /market/price (fast, weighted, knows your sales).
Showing a card detail screen, image, set info, attacks, full TCGPlayer breakdown? → GET /card/enrich (heavier, hits external API once, caches 24 h).
Need both? → call enrich for the visuals/metadata, then market/price for the actual offer.
